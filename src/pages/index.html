// WHAT IT DOES

Event-sourced attribution.
Integer money math. Postgres-native.

Every piece is a pure function you can test in isolation. The engine never touches money; it emits payout tasks.

01 / EVENT LOG

Append-only source of truth

One table. Typed events. No updates, no deletes. Every projection is a fold over this log.

02 / PROJECTIONS

Rebuildable state

Leads, payouts, and timelines derive from the event log. Drop a table, replay, done.

03 / MONEY

Integer minor units

No floats. Commission math uses exact integer arithmetic. Rounding rules are explicit.

04 / RULES

Qualification & routing

A vehicle-count threshold decides automated setup vs. manual review. Round-robin, least-loaded, or manual routing presets recommend an agent; your app decides whether to act on it.

05 / ESCROW

Escrow, ready to schedule

Commissions sit in a held state. release_due_commissions() does the release atomically inside Postgres; wiring it to pg_cron (or any scheduler) is a migration you write for your own project.

06 / AUTH

Vendor-neutral RLS

Policies resolve identity through a portable session variable, falling back to Supabase's auth.uid() only where it exists. Verified on plain Postgres, not just Supabase.

// HOW IT WORKS

Four steps.
No orchestration.

Everything runs inside your existing Node app and Postgres database.

app/api/webhooks/route.ts 
// Minimal install: engine + Postgres. Nothing else.
import { createTandemPool, applyTandemMigrations, withTandemSession } from 'tandem-crm/db';
import { qualifyLead, defaultTandemConfig } from 'tandem-crm';

const pool = createTandemPool(process.env.DATABASE_URL);
await applyTandemMigrations(pool);

// Adapters map external payloads into typed events, then write them
// inside a transaction scoped to the caller's identity.
await withTandemSession(pool, userId, async (client) => {
  const { status } = qualifyLead({ vehicleCount: 12 }, defaultTandemConfig);
  await client.query('insert into tandem.events (...) values (...)', [/* ... */]);
});

// release_due_commissions() runs inside Postgres. Wire it to pg_cron
// or any scheduler you already have. No separate worker process.

What's built.
What's coming.

This is the honest current state. No features are promised before they exist.

Live

Core

The engine, and the one module every install needs. Event log, projections, integer money math, idempotency, lead routing, an escrow release function ready for pg_cron, and an RLS layer verified on both Supabase and plain Postgres. Running in production on Supabase.

Live

Ramp

Agent onboarding and certification. Its own event log, reducers, and RLS, sitting next to Core's. An agent works through the required steps and certifies themselves once they're done; your app decides what certification unlocks.

In progress

CRM / Admin UI

A reference dashboard in examples/dashboard, built on shadcn/ui. The overview page and the Ramp onboarding flow work end to end against a real Postgres database. Leads, payouts, and routing screens are next.

Planned

Coaster

Clawbacks, disputes, and payout blocking. The brakes on the commission engine.

Live

Auth adapter

Three functions are all Tandem needs from your identity provider: who's signed in, and their membership row. Implement them once against Supabase Auth, Clerk, BetterAuth, or a table you built yourself, and RLS enforces the rest.

Planned

Tandem Cloud

Managed hosting. Provisioning, monitoring, upgrades. Not started. Not before the open-source packages have real users.
